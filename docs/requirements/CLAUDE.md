## Назначение

Wiki проекта — структурированная база знаний. Claude ведёт wiki, человек направляет.

## Структура

```
raw/            — инбокс необработанных экспортов (после обработки пуст)
raw/recycled/   — архив обработанных снапшотов; самый свежий = текущий канон
wiki/index.md   — оглавление
wiki/log.md     — append-only журнал операций
wiki/feature/   — фичи и флоу
wiki/umbrella/  — зонтики версионируемых методов
wiki/method/    — API-методы
```

## Категории и граф

Граф: `feature → umbrella → method`. Направление строгое.

- **feature** — описание с позиции бизнес-аналитика. Ссылается на umbrella, не на конкретную версию метода.
- **umbrella** — точка входа семейства методов (только при наличии нескольких версий). Ссылается только вниз: на методы своего семейства.
- **method** — атомарное описание API-метода. `## Related pages` отсутствует, `[[wikilinks]]` нигде нет.

Рёбра — только в `## Related pages`, только вниз: parent → child.

## Теги

Только во frontmatter, без inline-тегов. Каждая страница несёт ровно один тег категории по папке.

- `feature` / `umbrella` / `method` — по папке
- `stub` — единственный признак заглушки; снимается только явным удалением тега
- `root` — системные файлы (CLAUDE.md, index.md, log.md); без тегов категории

Frontmatter: теги без `#`. Поиск: `tag:#method`, `tag:#stub`.

## Формат страниц

Пустые поля остаются, структура соблюдается всегда. Заглушка = та же структура + тег `stub`.

**Feature** — обязательные секции:
- Frontmatter + `# Заголовок`
- Meta-блок: `**Summary**`, `**Sources**`, `**Last updated**`
- Meta-таблица: Analyst, Date, Description
- Resources-таблица: Design, Specs
- `## Requirements` — таблица `| # | Requirement | Description |`
- `## Version agenda` — таблица `| Update tag | Analyst | Date | Task | Description |`
- `## Related pages` — ссылки вверх по иерархии

**Method** — обязательные секции:
- Frontmatter + `# method-name`
- Meta-блок: `**Summary**`, `**Sources**`, `**Last updated**`
- Meta-таблица: Analyst, Publication date, Description
- `### Signature` — kotlin-блок
- `### Parameters` — таблица `| Parameter | Req | Type | Description |`; если нет — текст «Параметров нет.», секция `### Request:` опускается
- `### Response parameters`
- `### Request:` — JSON с именованными параметрами и примерными значениями
- `### Response:` — полный пример JSON
- `### Errors List:` — таблица `| Exception | Condition |`

## Стилевые правила method-страниц

- **Req**: `Y` / `N`. Никаких `Yes`/`No`.
- **Enum в Description**: вертикально через `<br>\* value` строчными буквами.
- **Enum в JSON**: значения строчными (`"open"`, не `"Open"`).
- **JSON**: вложенные объекты раскрыты полностью, nullable-поля показывать явно (`"mergedAt": null`).
- **Wrapper-типы в Request**: разворачивать до строки (`Peer.Id("x")` → `"x"`).

## Ответы на вопросы

1. Читать `wiki/index.md` → найти релевантные страницы.
2. Синтезировать ответ, сослаться на конкретные страницы `(source: file.md)`.
3. Нет ответа в wiki — сказать прямо.
4. Ценный ответ на основе `raw/` — предложить сохранить как новую страницу.

Противоречие между источниками — указать явно. Утверждение без источника — пометить как требующее проверки.

## Lint

- Противоречия между страницами.
- Сироты (нет входящих ссылок) и концепты без даже заглушки.
- Заглушки давно не наполненные.
- Теги: категория по папке; заполненные без `stub`; root без категории.
- Каждый файл wiki описан в `index.md` через `[name](path.md)`, не `[[wikilinks]]`.
- Изоляция методов: в `wiki/method/` нет `[[wikilinks]]`.
- Граф: feature не ссылается напрямую на версию при наличии umbrella; umbrella — только вниз; `## Related pages` не содержит ссылок вверх.
- Нет конструкций `[[X]](url)`. Методы и фичи, упомянутые в ячейках требований, оформляются как markdown-ссылки на соответствующий файл. Типы данных, поля, enum-значения — backtick-нотация `` `name` ``.
- Feature-страницы содержат Version agenda, meta-таблицу, Resources. Method-страницы — не содержат.
- Method-страницы соответствуют стилевым правилам.
- CLAUDE.md правился в этой сессии → чеклист читаемости конституции.
- Результат — нумерованный список с предложениями по исправлению.

## Правила

- Имена файлов: строчные буквы с дефисами.
- Язык: позиция бизнес-аналитика — что делает продукт, без платформы и деталей реализации.
- Тег категории не снимается никогда.
- **Золотое правило:** при неуверенности — спрашивать, не угадывать.
