# Compose

Проект живёт на собственной дизайн-системе `AppTheme` (цвета, типографика, `AppMotion`, `AppShapes`,
`Elevation`), не на Material. Цвета берутся ролями; `ColorPalette` закрыт для компонентов.

## Наружу — `State<T>`, чтение по месту

Значение, которое читает Compose, держится в `mutableStateOf`, а наружу отдаётся как `State<T>`.
Читается оно в той фазе, которой нужно: `graphicsLayer`, `drawBehind`, листовой композабл.

```kotlin
// нельзя: читатель подписан там, где получил значение
val offset: Offset get() = …

// нужно: State можно передать дальше, не читая
val offset: State<Offset> = derivedStateOf { … }
```

**Почему:** готовое значение подписывает читателя на том уровне, где он его получил, — а `State`
передаётся дальше нетронутым и читается ровно там, где нужен. Промах на один уровень (чтение в теле
композабла вместо фазы рисования) уже приводил к бесконечному циклу измерения.

## Превью — через `@PreviewParameter`

Варианты компонента подаются провайдером, а не размножаются копиями вызова внутри одной
превью-функции и не дублируются по нескольким.

```kotlin
@Preview
@Composable
private fun MessageChipPreviewLight(
  @PreviewParameter(MessageChipPreviewProvider::class)
  chip: MessageChipPreview
) {
  PreviewColumn(colorTheme = ColorTheme.Light) {
    MessageChip(text = chip.text, isMine = chip.isMine, state = chip.state)
  }
}
```

На тему — своя функция (Light/Dark), обе берут один и тот же провайдер.

**Почему:** варианты, слитые в один кадр, скрывают, какой именно сломался, и колонка растёт в высоту
с каждым новым состоянием. Через провайдер новое состояние добавляется в одном месте и появляется
сразу во всех темах.

## Моки — в `Mocks.kt`

Всё, что относится к мокам, — функции, классы, наборы данных, провайдеры превью — живёт в отдельном
файле `Mocks.kt`, лежащем плоско рядом с тем, что он мокает: `screen/<name>/Mocks.kt`,
`components/Mocks.kt`. Правило «один класс — один файл» здесь не действует.

**Почему:** мок виден как мок по имени файла, а не по комментарию внутри, и уезжает целиком вместе с
файлом, когда появляются настоящие данные. Разложенный по entity-пакетам, он переживёт свою
надобность и станет неотличим от настоящей модели.
